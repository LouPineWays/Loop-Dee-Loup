# Skill observer

Observe skills while doing normal work; do not add a second narration stream.

Log a finding only when there is concrete evidence that a skill or rule:

- caused or nearly caused an incorrect action;
- required avoidable rereading, repetition, founder intervention, or review;
- contradicted controlling repository authority;
- omitted a recurring guardrail;
- routed work to an unnecessarily expensive model or workflow.

Record: date, skill/rule, triggering task, observed failure, evidence link, consequence, and smallest candidate correction. Keep hypotheses explicitly labeled.

At the earliest safe boundary, decide whether the defect is incidental or systemic. If systemic and the smallest correction is low-risk and within the active process-improvement authority, update the governing skill in the same slice and verify it. Otherwise create one accepted independent improvement outcome; do not accumulate vague cleanup notes.

Never rewrite a skill mid-step when doing so would change the rules beneath correctness-sensitive work. Apply the corrected version from the next clean session boundary. Prefer mechanisms and deterministic checks over longer prose.
